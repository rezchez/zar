# زارفولیو (Zarfolio)

زارفولیو یک راهکار نرم‌افزاری مدرن و تحت وب برای مدیریت مالی، حسابداری طلا، مسکوکات و شمش، صندوق‌های چندارزی و حساب‌های بانکی است. این پروژه با استفاده از معمار‌های نوین **Next.js (App Router)** و **PocketBase** به عنوان پایگاه داده سبک و پرسرعت، امکانات پیشرفته‌ای شامل حسابداری دوطرفه، ویجت‌های سفارشی‌پذیر داشبورد و کنترل سطوح دسترسی را فراهم می‌سازد.

---

## قابلیت‌های اصلی

- **سیستم مدیریت ویجت‌های داشبورد:** قابلیت سفارشی‌سازی کامل داشبورد شامل فعال/غیرفعال‌سازی، تغییر اندازه در ۳ حالت (`کوچک`، `متوسط`، `بزرگ`) و ذخیره ماندگار چیدمان.
- **ویجت زنده موجودی وجه نقد (`cash-balance`):** نمایش صندوق‌های مالی ارزی و ریالی بر اساس تنها مرجع حقیقت (تراکنش‌های صندوق و موجودی اول دوره).
- **موتور حسابداری دوطرفه:** رعایت اصل تراز بودن اسناد حسابداری، نگاشت حساب‌های معین و تفصیلی سطح ۴ (`pbc_chart_of_accounts`) و ثبت دفاتر.
- **مدیریت مسکوکات و شمش طلا:** کاتالوگ جامع سکه‌های استاندارد ایران (امامی، بهار آزادی، نیم، ربع) و شمش با محاسبه وزن معادل عیار ۷۵۰ (۱۸ عیار).
- **صندوق‌های چندارزی:** قانون ثبت یک صندوق به ازای هر واحد پولی در سطح دیتابیس (`idx_cash_funds_currency`) با پشتیبانی از تومان، دلار، یورو، درهم، پوند و سایر ارزها.
- **یکپارچگی با بانک‌های ایران:** نگاشت بیش از ۳۰ بانک ایرانی با لوگو اختصاصی، اعتبارسنجی شماره شبا (`IR` + ۲۴ رقم)، دسته‌چک و چک صیادی.
- **کنترل دسترسی مبتنی بر نقش (RBAC):** سطوح دسترسی مدیر ارشد، مدیر و کاربر عادی، به همراه امکان تعریف دسترسی‌های سفارشی برای هر کاربر (`customPermissions`).
- **امنیت و حریم خصوصی:** جلوگیری از Enumeration در ورود، محدودسازی نرخ درخواست‌ها (Rate Limiting)، رمزنگاری AES-256-GCM اعلانات و نشست‌های امن با کوکی HTTP-only.
- **پشتیبانی کامل از فارسی و RTL:** رابط کاربری کاملاً راست‌چین، تقویم شمسی، تبدیل اعداد به فارسی و پشتیبانی از PWA.

## فناوری‌های مورد استفاده

- **بخش فرانت‌اند (Frontend):** Next.js (App Router)، React 19، Tailwind CSS، Framer Motion، Lucide React، Morphicons
- **زبان برنامه‌نویسی:** TypeScript
- **محیط اجرا و مدیریت پکیج:** Bun
- **پایگاه داده و بک‌اند:** PocketBase
- **گزارش‌گیری و خروجی:** `pdfkit` برای تولید PDF و `xlsx` برای خروجی اکسل
- **محیط تست:** Bun Test (`bun test`)

## معماری پروژه

پروژه زارفولیو دارای معماری مجزا و مستقل برای فرانت‌اند و بک‌اند است:

- **فرانت‌اند (`frontend/`):** شامل صفحات داشبورد، فرم‌های ورود اسناد مالی، گزارش دفاتر مشتریان و مسیرهای API پروکسی (`app/api/`) جهت احراز هویت و برقراری ارتباط امن با دیتابیس.
- **بک‌اند و مایگریشن‌ها (`backend/pb_migrations/`):** ساختار کالکشن‌ها و مایگریشن‌های PocketBase که به صورت فایل‌های JavaScript مدیریت می‌شوند.
- **اصل تنها مرجع حقیقت (Single Source of Truth):** موجودی‌های مالی (صندوق، بانک، طلا) بدون ایجاد داده‌های متوازی یا تکراری، به صورت مستقیم از روی تراکنش‌های واقعی و اسناد اول دوره محاسبه می‌شوند.

## معماری ویجت‌های داشبورد

داشبورد زارفولیو بر پایه معماری پویای ویجت‌ها طراحی شده است:

```text
صفحه داشبورد (Dashboard Page)
    └── DashboardWidgetContainer
            ├── ثبت ویجت‌ها (lib/dashboard-widgets.ts)
            │     ├── quick-actions (میان‌برهای سریع)
            │     ├── market-ticker (قیمت لحظه‌ای طلا و ارز)
            │     ├── cash-balance (موجودی وجه نقد)
            │     ├── bank-balances (موجودی بانک‌ها)
            │     ├── gold-trackers (شاخص‌های تراز وزنی و ریالی)
            │     └── jalali-calendar (تقویم خورشیدی)
            ├── اندازه‌های ویجت (کوچک، متوسط، بزرگ)
            ├── کنترل‌های نمایش/مخفی‌سازی و چیدمان
            └── ذخیره‌سازی تنظیمات کاربر (کالکشن dashboard_preferences)
```

هر ویجت از ۳ اندازه واکنش‌گرا پشتیبانی می‌کند و تنظیمات کاربر (نمایش، اندازه، ترتیب) به صورت خودکار در کالکشن `dashboard_preferences` ذخیره می‌شود.

## کالکشن‌های دیتابیس (PocketBase)

جدول کالکشن‌های اصلی سیستم:

| نام کالکشن | توضیح | مرجع اصلی |
|---|---|---|
| `users` (`_pb_users_auth_`) | کاربران، نقش‌ها (`admin`, `manager`, `user`) و دسترسی‌های خاص | احراز هویت و دسترسی |
| `currencies` | فهرست ارزها (کد، نام، نماد، تعداد اعشار) | کاتالوگ ارزها |
| `cash_funds` | صندوق‌های وجه نقد متصل به ارز و حساب تفصیلی | معرفی صندوق‌ها |
| `cash_transactions` | تراکنش‌های صندوق (`direction: 'in' \| 'out'`) | **محاسبه موجودی صندوق** |
| `bank_accounts` | حساب‌های بانکی، شماره شبا و وضعیت دسته‌چک | معرفی حساب‌های بانکی |
| `bank_transactions` | تراکنش‌های حساب بانکی | محاسبه موجودی بانک |
| `pbc_chart_of_accounts` | کدینگ کل، معین و تفصیلی حسابداری | اسناد و دفاتر حسابداری |
| `coin_types` | کاتالوگ سکه و شمش طلا | موجودی سکه و شمش |
| `dashboard_preferences` | تنظیمات چیدمان و اندازه‌های ویجت‌های هر کاربر | تنظیمات داشبورد |
| `app_settings` | تنظیمات کلی سازمان، سال مالی و قالب‌های چاپ | تنظیمات برنامه |

## راهنمای نصب و اجرا

### پیش‌نیازها

- **Bun** (نسخه v1.2.0 یا بالاتر)
- **Node.js** (نسخه v20 یا بالاتر)
- **PocketBase** (نسخه v0.22 یا بالاتر)

### مراحل اجرای پروژه در محیط توسعه

۱. **دریافت سورس کد:**
   ```bash
   git clone https://github.com/rezchez/zar.git
   cd zar
   ```

۲. **نصب وابستگی‌ها:**
   ```bash
   cd frontend
   bun install
   ```

۳. **تنظیم متغیرهای محیطی:**
   یک فایل `.env.local` در پوشه `frontend/` ایجاد کنید:
   ```env
   POCKETBASE_URL=http://127.0.0.1:8090
   POCKETBASE_SUPERUSER_EMAIL=admin@example.com
   POCKETBASE_SUPERUSER_PASSWORD=securepassword
   NEXT_PUBLIC_BASE_URL=http://localhost:3000
   ```

۴. **اجرای دیتابیس PocketBase:**
   دیتابیس را همراه با فایل‌های مایگریشن اجرا کنید:
   ```bash
   pocketbase serve --dir=../pb_data --migrationsDir=../backend/pb_migrations
   ```

۵. **اجرای سرور توسعه Next.js:**
   ```bash
   cd frontend
   bun run dev
   ```
   سپس آدرس `http://localhost:3000` را در مرورگر باز کنید.

## تست و سنجش کیفیت

پروژه زارفولیو دارای تست‌های واحد و یکپارچه‌سازی با **Bun Test** است:

```bash
cd frontend
bun test
```

موارد مورد ارزیابی در تست‌ها:
- محاسبات موجودی اول دوره و جهت تراکنش‌های صندوق (`tests/cash-funds-opening-balance.test.ts`)
- ثبت ویجت‌های داشبورد و نرمال‌سازی تنظیمات کاربر (`tests/dashboard-widgets.test.ts`)
- موتور ثبت اسناد حسابداری و تراز بودن سندها (`tests/accounting-posting-engine.test.ts`)
- محاسبات وزن طلا و عیار معادل ۷۵۰ (`tests/coin-entry.test.ts`)
- اعتبارسنجی شماره شبا و بانک‌های ایران (`tests/bank-icons.test.ts`)
- رمزنگاری AES-256-GCM اعلانات و محدودسازی نرخ درخواست (`tests/notification-flow.test.ts`)

## نکات امنیتی

- **اعتبارسنجی سمت سرور:** تمام مسیرهای API هویت کاربر را با `getServerAuthContext()` بررسی کرده و دسترسی‌ها را با `hasPermission()` کنترل می‌کنند.
- **ایزوله‌سازی داده‌ها:** قوانین دسترسی PocketBase (API Rules) محدوده داده‌ها را برای هر کاربر قفل می‌کنند (`user = @request.auth.id`).
- **محافظت در برابر Brute-force:** مسیرهای احراز هویت دارای Rate Limiter سمت سرور بر اساس IP هستند.
- **رمزنگاری در حالت سکون:** اعلانات حساس قبل از ذخیره در دیتابیس با کلید AES-256-GCM رمزنگاری می‌شوند.
