# راهنمای کامل Migration تنظیمات مرکزی، ثبت اسناد و شماره‌گذاری در Zarfolio

این راهنما برای تمامی کاربران (حتی افراد مبتدی بدون دانش قبلی از PocketBase) تهیه شده است تا بتوانند به ساده‌ترین شکل ممکن تغییرات دیتابیس سامانه حسابداری **Zarfolio** را اعمال و بررسی نمایند.

---

## ۱. معرفی ساده

فایل‌های **Migration** در سامانه، اسکریپت‌های استانداردی هستند که تغییرات دیتابیس را به‌صورت خودکار، امن و بدون دستکاری دستی اعمال می‌کنند.

این migration تغییرات زیر را در سامانه اعمال می‌نماید:
- **تنظیمات مرکزی عیار مبنا:** عیارهای مبنای طلا (۷۵۰)، پلاتین (۸۰۰) و نقره (۹۲۵).
- **تاریخ شروع سال مالی:** امکان تنظیم تاریخ جلالی به‌صورت پایدار.
- **پیشوند شماره سند:** تنظیم پیشوند پیش‌فرض شماره‌گذاری اسناد (مانند `سند-`).
- **شماره‌گذاری ترتیبی مستقل برای هر طرف‌حساب:** تولید شماره سند اختصاصی برای هر مشتری به همراه snapshot پیشوند.
- **قید یکتایی (Unique Index):** جلوگیری از ثبت شماره ترتیبی تکراری برای یک طرف‌حساب (`customerId + documentSequence`).
- **تکمیل داده‌های قدیمی (Backfill):** شماره‌گذاری منظم و سازگار برای اسناد ثبت‌شده قبلی بدون حذف داده.

---

## ۲. هشدار بسیار مهم: تهیه نسخه پشتیبان (Backup)

قبل از اجرای هرگونه migration، حتماً از داده‌های خود پشتیبان بگیرید.

### روش تهیه Backup:
1. پروژه یا دیتابیس PocketBase را متوقف کنید.
2. پوشه `pb_data/` را در ریشه پروژه پیدا کرده و یک کپی کامل از آن در محلی امن قرار دهید:

```bash
# در لینوکس / Xubuntu:
cp -r pb_data pb_data_backup_$(date +%Y%m%d)
```

در ویندوز می‌توانید روی پوشه `pb_data` راست کلیک کرده و گزینه Copy و سپس Paste را بزنید.

---

## ۳. پیش‌نیازها

- نصب بودن مدیریت پکیج **Bun** (نسخه ۱.۱ یا بالاتر)
- وجود فایل‌های پروژه Zarfolio
- دسترسی به ترمینال (Terminal در لینوکس یا CMD/PowerShell در ویندوز)
- اجرای تمام دستورات از **پوشه اصلی (Root)** پروژه

---

## ۴. تشخیص سیستم‌عامل

اسکریپت‌های درون پوشه `migrate/` برای دو سیستم‌عامل لینوکس/مک و ویندوز آماده شده‌اند:
- **لینوکس / Xubuntu / مک:** اسکریپت‌های با پسوند `.sh`
- **ویندوز:** اسکریپت‌های با پسوند `.bat`

---

## ۵. اجرای Migration در Linux / Xubuntu

۱. وارد ترمینال شوید و به پوشه ریشه پروژه بروید:
```bash
cd /path/to/zarfolio
```

۲. دسترسی اجرای اسکریپت‌ها را فعال کنید:
```bash
chmod +x migrate/*.sh
```

۳. اسکریپت migration را اجرا کنید:
```bash
./migrate/run-migration.sh
```

**توضیح:** این اسکریپت به‌صورت امن فایل‌های migration را با پوشه استاندارد `pb_migrations/` همگام کرده و اسکریپت به‌روزرسانی Schema را اجرا می‌نماید.

---

## ۶. اجرای Migration در Windows

۱. پنجره `Command Prompt (cmd)` را باز کرده و به مسیر پروژه بروید:
```cmd
cd C:\path\to\zarfolio
```

۲. اسکریپت را اجرا کنید:
```cmd
migrate\run-migration.bat
```

---

## ۷. بررسی موفقیت Migration

برای اطمینان از صحت تغییرات اعمال‌شده، اسکریپت verify را اجرا کنید:

**در لینوکس:**
```bash
./migrate/verify-migration.sh
```

**در ویندوز:**
```cmd
migrate\verify-migration.bat
```

در صورت موفقیت، پیام تایید فیلدها و ساختار دیتابیس نمایش داده می‌شود.

---

## ۸. اجرای پروژه پس از Migration

پس از اجرای موفق migration، پروژه را اجرا یا کامپایل کنید:

۱. نصب و همگام‌سازی وابستگی‌ها:
```bash
bun install
```

۲. اجرای پروژه در حالت توسعه:
```bash
bun run dev
```

۳. کنترل کیفیت و تست ساخت کامل:
```bash
bun run lint
bunx tsc --noEmit
bun run build
```

---

## ۹. راهنمای خطاهای رایج

| خطا | علت احتمالی | راه‌حل |
|---|---|---|
| `Permission denied` در لینوکس | عدم داشتن دسترسی اجرای اسکریپت | دستور `chmod +x migrate/*.sh` را اجرا کنید. |
| `bun: command not found` | عدم نصب Bun در سیستم | Bun را از سایت bun.sh نصب کنید. |
| `database locked` | روشن بودن هم‌زمان PocketBase هنگام تغییر فایل دیتابیس | سرویس PocketBase را متوقف کنید و مجدداً اسکریپت را بزنید. |
| `unique index failed` | وجود شماره سند تکراری ناشی از داده دستکاری‌شده قدیمی | اسکریپت `verify-migration` را اجرا کرده یا داده‌های تکراری را بررسی نمایید. |

---

## ۱۰. Rollback و بازیابی

در صورت نیاز به بازگردانی تغییرات، اسکریپت rollback را اجرا کنید:

**در لینوکس:**
```bash
./migrate/rollback-migration.sh
```

**در ویندوز:**
```cmd
migrate\rollback-migration.bat
```

**نکته مهم:** به منظور حفظ داده‌های مالی کاربران، اسناد و مبالغ در عملیات rollback پاک نمی‌شوند و صرفاً قیدهای نمایه آزاد می‌شوند. در صورت نیاز به بازگشت کامل دیتابیس، نسخه پشتیبان پوشه `pb_data/` را جایگزین نمایید.
