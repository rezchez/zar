# مستند توسعه‌دهنده: سرویس مرکزی مدیریت و بهینه‌سازی تصاویر (Image Service) در Zarfolio

این سند معماری، نحوه عملکرد و راهنمای توسعه سیستم مرکزی پردازش و بهینه‌سازی تصاویر را در Zarfolio توضیح می‌دهد.

---

## ۱. محل قرارگیری Image Service در پروژه کجاست؟

کدهای ماژولار زیرساخت تصویر در مسیر `frontend/lib/images/` پیاده‌سازی شده‌اند:

```text
frontend/lib/images/
├── types.ts              # تعاریف داده‌ها، اینترفیس‌ها و اهداف تصویر (ImagePurpose)
├── config.ts             # تنظیمات پیش‌فرض برای هر نوع تصویر (کیفیت، حداکثر حجم، ابعاد)
├── image-processor.ts    # موتور اعتبارسنجی جادویی بایت‌ها، تغییر اندازه، کراپ هوشمند، حذف متادیتا و تبدیل WebP
├── image-storage.ts      # توابع نام‌گذاری امن، تولید آدرس‌های نسخه‌دار (Cache-Busting) و ساخت File
├── image-service.ts      # کلاس و نمونه مرکزی ImageService (هماهنگ‌کننده سطح بالا)
└── index.ts              # نقطه خروجی واحد (Barrel export)
```

---

## ۲. چگونه تصویر پردازش می‌شود؟

فرآیند پردازش تصویر در متد `imageService.processUpload` یا `imageService.process` به صورت ترتیبی و چندمرحله‌ای انجام می‌شود:

1. **اعتبارسنجی اولیه (Magic Bytes & Size)**:
   - ابتدا بایت‌های ابتدایی فایل (`Magic Bytes`) بررسی می‌شوند تا اطمینان حاصل شود داده ارسالی واقعاً یک تصویر (JPEG, PNG یا WebP) است و فایل اسکریپت یا بدافزار با پسوند جعلی نیست.
   - حجم فایل با سقف مجاز تعیین‌شده برای آن بخش مقایسه می‌شود.
   - ساختار بیت‌استریم تصویر توسط کتابخانه باینری `sharp` بررسی و متادیتای آن پارس می‌شود.
2. **چرخش خودکار بر اساس تگ جهت EXIF**:
   - متد `.rotate()` تصویر را طبق چرخش اصلی دوربین کاربر تنظیم می‌کند تا تصاویر پرتره گوشی به شکل وارونه یا کج ظاهر نشوند.
3. **تغییر اندازه و کراپ هوشمند (Smart Crop)**:
   - با الگوریتم کراپ هوشمند آنتروپی (`sharp.strategy.entropy` با فال‌بک به `center`)، بخش اصلی و مهم تصویر متمرکز شده و بدون کشیدگی (No Distortion) به ابعاد هدف برش می‌خورد.
4. **تبدیل به فرمت مدرن WebP و حذف EXIF**:
   - تصویر با کیفیت استاندارد به فرمت WebP فشرده شده و تمام اطلاعات حریم خصوصی و دوربین از آن حذف می‌شود.

---

## ۳. آواتار کاربر چگونه ذخیره می‌شود؟

1. فرانت‌اند در صفحه تنظیمات حساب کاربری (`/dashboard/account`) تصویر انتخابی را از طریق فرم `PATCH /api/account/profile` ارسال می‌کند.
2. کنترل‌کننده API با فراخوانی `imageService.processUpload`:
   - تصویر را تایید و پردازش می‌کند.
   - فایلی با پسوند `.webp` با نوع استاندارد `image/webp` و نام تصادفی و امن ایجاد می‌نماید.
3. فایل وب‌پی پردازش‌شده به کلاینت PocketBase ارسال می‌شود و به فیلد بومی `avatar` در رکورد کاربر متصل می‌گردد.
4. پاکت‌بیس فایل را در دایرکتوری بومی خود در مسیر زیر ذخیره می‌کند:
   ```text
   backend/pb_data/storage/_pb_users_auth_/<userId>/<generated_filename>.webp
   ```

---

## ۴. فرمت WebP چگونه تولید می‌شود؟

تبدیل فرمت با استفاده از موتور باینری و بهینه `sharp` انجام می‌شود:

```ts
transformer.webp({
  quality: 85, // کیفیت بهینه در بازه استاندارد 82 الی 85
  effort: 4,   // تعادل عالی بین سرعت فشرده‌سازی CPU و حجم خروجی
});
```

این تبدیل موجب کاهش حجم بین ۶۰ تا ۹۵ درصد نسبت به فایل‌های اصلی دوربین بدون افت محسوس کیفیت بصری می‌شود.

---

## ۵. محدودیت حجم ورودی چیست؟

- **سقف مجاز آواتار**: `5 MB` (`5 * 1024 * 1024` بایت).
- در صورتی که کاربری فایلی بزرگتر از ۵ مگابایت ارسال کند:
  - در فرانت‌اند با بررسی پیش از آپلود، پیام خطای فارسی فوری نمایش داده می‌شود.
  - در بک‌اند قبل از هرگونه تخصیص بافر سنگین یا پردازش، درخواست رد شده و پاسخ وضعیت `400` با پیام خطای کنترل‌شده `حجم فایل نباید بیشتر از ۵ مگابایت باشد.` بازگردانده می‌شود.

---

## ۶. ابعاد آواتار چیست؟

- **ابعاد هدف**: دقیقاً `256 × 256` پیکسل.
- نسبت ابعاد نهایی کاملاً مربع (`1:1`) است.
- در صورتی که تصویر ورودی افقی (Landscape) یا عمودی (Portrait) باشد، برش با حفظ تناسب و تمرکز بر ثقل محتوا انجام می‌شود و تصویر کشیده نمی‌شود.

---

## ۷. ذخیره‌سازی (Storage) چگونه مدیریت می‌شود؟

- **امنیت مسیر و نام فایل**:
  - نام فایل ارسالی توسط کلاینت هرگز مستقیماً ذخیره نمی‌شود تا از حملات Path Traversal یا ذخیره کاراکترهای مخرب جلوگیری شود.
  - نام فایل توسط متد `generateSafeFileName` بر اساس الگوی زیر ساخته می‌شود:
    ```text
    avatar_<entityId>_<timestamp>_<randomHex>.webp
    ```
- **عدم وابستگی سفت‌وسخت**:
  - کلاس `PocketBaseImageStorageProvider` وظیفه تعامل با پاکت‌بیس را بر عهده دارد، اما اینترفیس `ImageStorageProvider` به شکلی طراحی شده که در آینده بتوان ارائه‌دهنده‌های ذخیره‌سازی ابری دیگر (مانند S3، آبجکت استوریج آروان و...) را بدون تغییر کد پردازشگر تصویر جایگزین کرد.

---

## ۸. حذف آواتار قبلی چگونه انجام می‌شود؟

- **اصل تقدم امنیت داده**:
  آواتار قبلی هرگز پیش از موفقیت قطعی ذخیره آواتار جدید حذف نمی‌شود.
- **روند ذخیره و جایگزینی**:
  ```text
  Upload -> Validate Magic Bytes -> Process to WebP -> Store New -> Update Record -> Clean Old
  ```
  هنگامی که رکورد در پاکت‌بیس با آواتار جدید بروزرسانی شد، پاکت‌بیس به صورت خودکار فایل فیزیکی قبلی و ریزعکس‌های قدیمی را از دیسک پاکسازی می‌کند.
- **جلوگیری از فایل‌های یتیم (Orphan Files)**:
  در صورت بروز هرگونه خطا در زمان پردازش یا بروزرسانی دیتابیس، دیتابیس بدون تغییر مانده و آواتار قبلی کاربر حفظ می‌شود.
- **حذف صریح توسط کاربر**:
  متد `DELETE /api/account/profile` با ارسال مقدار خالی برای فیلد `avatar`، تصویر قبلی را حذف و لاگ رخداد امنیتی ثبت می‌کند.

---

## ۹. چگونه جلوی نمایش تصویر قبلی از کش مرورگر (Cache Busting) گرفته می‌شود؟

مرورگرها معمولاً تصاویر را برای عملکرد بهتر در حافظه کش ذخیره می‌کنند. برای رفع این مشکل از دو مکانیزم هم‌زمان استفاده شده است:

1. **تغییر نام فیزیکی فایل**:
   با هر بار آپلود، به دلیل وجود زمان و بایت‌های تصادفی در نام فایل (`avatar_<id>_<timestamp>_<rand>.webp`)، آدرس منبع تصویر تغییر می‌کند.
2. **پارامتر نسخه‌گذاری در آدرس URL**:
   متد `buildVersionedUrl` به انتهای آدرس تصویر پارامتر نسخه اضافه می‌کند:
   ```text
   http://.../api/files/_pb_users_auth_/<userId>/avatar_...webp?v=1789839105022
   ```
   این پارامتر بر اساس زمان فیلد `updated` رکورد کاربر ساخته می‌شود و باعث می‌شود تا کلاینت‌ها بلافاصله پس از ذخیره بدون نیاز به Hard Refresh، آواتار جدید را بارگذاری نمایند.

## ۱۰. چگونه در آینده نوع تصویر جدید (مانند کالا، سند، فاکتور) اضافه کنیم؟

معماری سیستم کاملاً Generic و ماژولار است. برای اضافه کردن بخش جدید (مثلاً تصویر کالا یا سنگ):

### مرحله ۱: اضافه کردن نوع به `ImagePurpose` در `types.ts`
(انواع متداول مانند `customer`، `product`، `jewelry`، `stone`، `diamond`، `document`، `invoice` و `gallery` از پیش در تایپ‌ها تعریف شده‌اند).

### مرحله ۲: تنظیم قوانین در `config.ts`
تنظیمات اختصاصی ابعاد، کیفیت و حجم مورد نظر را در `IMAGE_PURPOSE_CONFIGS` قرار دهید:

```ts
product: {
  maxSizeBytes: 10 * 1024 * 1024, // 10 MB
  targetWidth: 800,
  targetHeight: 800,
  format: 'webp',
  quality: 85,
  fit: 'inside', // حفظ نسبت بدون کراپ
  position: 'center',
  stripMetadata: true,
  allowedMimeTypes: ['image/jpeg', 'image/png', 'image/webp'],
}
```

### مرحله ۳: فراخوانی ساده در کنترل‌کننده مورد نظر
در API Route مربوطه، بدون تکرار منطق پردازش یا Sharp:

```ts
import { imageService } from '@/lib/images';

const uploadResult = await imageService.processUpload({
  file: uploadedFile,
  purpose: 'product',
  entityId: productId,
});

// استفاده از uploadResult.file برای ذخیره در دیتابیس
```

## ۱۱. اسکریپت مایگریشن آواتارهای قدیمی

برای تبدیل آواتارهای قبلی سیستم به تصاویر بهینه WebP با ابعاد ۲۵۶×۲۵۶، اسکریپت تکرارپذیر زیر ایجاد شده است:

```bash
cd frontend
bun run migrate:avatars
```

این اسکریپت به صورت امن دیتابیس را بررسی کرده، تصاویر غیر WebP را شناسایی و پردازش می‌کند، رکوردهای دیتابیس را بروزرسانی کرده و پس از اطمینان کامل، فایل‌های قدیمی و بندانگشتی را پاکسازی می‌کند.
