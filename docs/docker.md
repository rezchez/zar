# اجرای زر با Docker

این تنظیمات نسخهٔ production فرانت‌اند Next.js و فایل اجرایی فعلی PocketBase پروژه را در دو کانتینر اجرا می‌کند. هیچ سرویس دیتابیس دیگری لازم نیست.

## قبل از اولین اجرا

1. اجرای قبلی پروژه با `start.sh` را با Ctrl+C متوقف کنید. **هرگز دو PocketBase را روی یک پوشهٔ داده اجرا نکنید.**
2. با PocketBase خاموش، از داده‌ها، فایل‌های آپلودشده، پشتیبان‌های برنامه و تنظیمات محیطی نسخهٔ پشتیبان بگیرید:

   ```bash
   cd ~/Desktop/Zar
   tar -czf "$HOME/zar-before-docker-$(date +%Y%m%d-%H%M%S).tar.gz" \
     backend/pb_data frontend/app_backups frontend/.env
   ```

   این فایل شامل اطلاعات محرمانه است؛ آن را منتشر نکنید.
3. فایل `frontend/.env` و فایل اجرایی Linux amd64 در `backend/pocketbase` باید موجود باشند. همان کلیدهای رمزگذاری و تنظیمات قبلی حفظ شوند؛ تغییر کلیدها می‌تواند داده‌های رمزگذاری‌شده را غیرقابل‌خواندن کند.
4. پوشه‌های `backend/pb_data` و `frontend/app_backups` باید موجود و برای کاربر کانتینر قابل نوشتن باشند. روی سیستم فعلی UID/GID برابر 1000 است. در سیستم دیگر از متغیرهای `LOCAL_UID` و `LOCAL_GID` استفاده کنید.

## اجرا

```bash
cd ~/Desktop/Zar
sudo docker compose config --quiet
sudo docker compose up -d --build
sudo docker compose ps
sudo docker compose logs --tail=100
```

اولین ساخت نیازمند دانلود ایمیج‌ها و وابستگی‌هاست. فرانت‌اند بعد از سالم‌شدن PocketBase اجرا می‌شود.

- برنامه: `http://localhost:3000`
- مدیریت PocketBase: `http://localhost:8090/_/`

پورت‌ها فقط روی کامپیوتر خودتان منتشر شده‌اند؛ این تنظیم، استقرار عمومی با HTTPS نیست. برای پورت متفاوت، مثلاً `WEB_PORT=3001`، متغیر را با `sudo env WEB_PORT=3001 docker compose up -d --build` بدهید.

## داده‌ها و اسرار

- پوشهٔ فعلی `backend/pb_data` مستقیم به کانتینر متصل است؛ اطلاعات و فایل‌های فعلی حفظ می‌شوند و داخل ایمیج کپی نمی‌شوند.
- شروع PocketBase ممکن است migrationهای اجرا‌نشدهٔ همین پروژه را اعمال کند؛ برای همین پشتیبان‌گیری قبل از شروع ضروری است.
- پوشهٔ `frontend/app_backups` نیز مستقیم متصل است؛ پشتیبان‌های قبلی باقی می‌مانند.
- فایل `frontend/.env` فقط هنگام اجرا تزریق می‌شود و داخل ایمیج قرار نمی‌گیرد. فایل کامل خروجی `docker compose config` را به اشتراک نگذارید، چون ممکن است اسرار را نمایش دهد.
- دو کانتینر شبکهٔ یکسانی دارند و آدرس دیتابیس `http://127.0.0.1:8090` است؛ این کار لینک تصاویر و فونت‌هایی را که برنامه به مرورگر برمی‌گرداند نیز قابل‌دسترسی نگه می‌دارد. هر دو پورت در سرویس PocketBase منتشر می‌شوند. پورت 8090 را بدون اصلاح تولید لینک‌های برنامه تغییر ندهید.
- قالب raw در env_file از تفسیر علامت دلار در رمزها جلوگیری می‌کند؛ مقادیر این فایل باید بدون کوتیشن اضافی دور مقدار باشند.
- اطلاعات محرمانه را به build argumentها یا متغیرهای `NEXT_PUBLIC_*` ندهید.
- فرانت‌اند با Node.js اجرا می‌شود؛ Bun فقط در مرحلهٔ ساخت استفاده می‌شود.
- فایل اجرایی موجود PocketBase مخصوص Linux amd64 است. در سیستم ARM باید فایل اجرایی مناسب جایگزین و platform سرویس اصلاح شود.

## توقف، به‌روزرسانی و بازگشت به اجرای قبلی

```bash
sudo docker compose down
sudo docker compose up -d --build
```

توقف کانتینرها داده‌های متصل‌شده را حذف نمی‌کند. برای بازگشت به لانچر قبلی، اول `docker compose down` را اجرا کنید و سپس `./start.sh`؛ لانچر تغییر نکرده است.

## بررسی‌ها

```bash
cd frontend
bun test tests/
DOCKER_BUILD=1 NEXT_DIST_DIR=.next-docker-check bun run build
```

خروجی standalone تنها با `DOCKER_BUILD=1` فعال می‌شود و اجرای توسعهٔ قبلی را تغییر نمی‌دهد. Docker build فایل‌های محیطی میزبان را نمی‌خواند. بعد از اجرای کانتینرها، ورود به حساب، نمایش تصاویر، چاپ PDF و ساخت پشتیبان را بررسی کنید.
