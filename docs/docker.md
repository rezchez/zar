# اجرای زر با Docker

این تنظیمات نسخهٔ production فرانت‌اند Next.js، فایل اجرایی فعلی PocketBase و پراکسی HTTPS به نام Caddy را در سه کانتینر اجرا می‌کند. هیچ سرویس دیتابیس دیگری لازم نیست.

## قبل از اولین اجرا

1. اجرای قبلی پروژه با `start.sh` را با Ctrl+C متوقف کنید. **هرگز دو PocketBase را روی یک پوشهٔ داده اجرا نکنید.**
2. با PocketBase خاموش، از داده‌ها، فایل‌های آپلودشده، پشتیبان‌های برنامه و تنظیمات محیطی نسخهٔ پشتیبان بگیرید:

   ```bash
   cd ~/Desktop/Zar
   tar -czf "$HOME/zar-before-docker-$(date +%Y%m%d-%H%M%S).tar.gz" \
     backend/pb_data frontend/app_backups frontend/.env
   ```

   این فایل شامل اطلاعات محرمانه است؛ آن را منتشر نکنید.
3. فایل `frontend/.env` و فایل اجرایی Linux amd64 در `backend/pocketbase` باید موجود باشند. همان کلیدهای رمزگذاری و تنظیمات قبلی حفظ شوند؛ تغییر کلیدها می‌تواند داده‌های رمزگذاری‌شده را غیرقابل‌خواندن کند.
4. پوشه‌های `backend/pb_data` و `frontend/app_backups` باید موجود و برای کاربر کانتینر قابل نوشتن باشند. روی سیستم فعلی UID/GID برابر 1000 است. در سیستم دیگر از متغیرهای `LOCAL_UID` و `LOCAL_GID` استفاده کنید.

## اجرا

```bash
cd ~/Desktop/Zar
sudo docker compose config --quiet
sudo docker compose up -d --build
sudo docker compose ps
sudo docker compose logs --tail=100
```

اولین ساخت نیازمند دانلود ایمیج‌ها و وابستگی‌هاست. فرانت‌اند بعد از سالم‌شدن PocketBase اجرا می‌شود.

- برنامه: `http://localhost:3000`
- مدیریت PocketBase: `http://localhost:8090/_/`
- آدرس عمومی برنامه: `https://86.104.86.188`

پورت‌های 3000 و 8090 فقط روی کامپیوتر خودتان منتشر می‌شوند؛ فقط پورت TCP 443 برای HTTPS عمومی است. برای پورت محلی متفاوت، مثلاً `WEB_PORT=3001`، متغیر را با `sudo env WEB_PORT=3001 docker compose up -d --build` بدهید.

## HTTPS روی IP ثابت

1. در مودم، پورت **TCP 443 بیرونی را به TCP 443 روی 192.168.2.172** فوروارد کنید و این IP داخلی را در DHCP مودم رزرو کنید. پورت‌های 3000 و 8090 را فوروارد نکنید. مدیریت از راه دور مودم نباید پورت 443 را اشغال کند.
2. اگر فایروال میزبان فعال است، ورودی TCP 443 باید مجاز باشد. این فایل‌ها فایروال میزبان را تغییر نمی‌دهند.
3. برای اعمال تنظیمات جدید روی نصب موجود، ابتدا ساخت و دانلود را انجام دهید؛ سپس با توقف کوتاه کانتینرها شبکه را بازسازی کنید:

   ```bash
   cd ~/Desktop/Zar
   sudo docker compose config --quiet &&
   sudo docker compose build &&
   sudo docker compose pull caddy &&
   sudo docker compose down &&
   sudo docker compose up -d --no-build
   sudo docker compose logs --tail=80 caddy
   ```

Caddy برای IP عمومی از Let's Encrypt با پروفایل `shortlived` گواهی عمومی می‌گیرد و آن را خودکار تمدید می‌کند. اعتبار این گواهی‌ها حدود شش روز است؛ برای صدور و تمدید، اینترنت و دسترسی ورودی پورت 443 باید برقرار باشند. اعتبارسنجی TLS-ALPN-01 است؛ پورت 80 لازم نیست. تا قبل از فوروارد صحیح، صدور گواهی ممکن نیست و HTTPS آمادهٔ استفاده نیست. هنگام تأخیر صدور، لاگ Caddy را بررسی کنید؛ هشدار امنیتی مرورگر را دور نزنید.

فقط درخواست‌های GET/HEAD مسیر `/api/files/*` به PocketBase می‌روند؛ مجوز فایل‌ها همچنان توسط PocketBase بررسی می‌شود. سایر مسیرها به Next.js می‌روند و پنل مدیریت و API عمومی PocketBase منتشر نمی‌شوند. لینک تصاویر و فونت‌های خروجی برنامه با `POCKETBASE_PUBLIC_URL` به HTTPS عمومی تبدیل می‌شوند؛ ارتباط داخلی برنامه با دیتابیس روی loopback باقی می‌ماند. این تنظیم جایگزین بررسی امنیتی برنامه پیش از انتشار اطلاعات حساس نیست.

گواهی‌ها، کلید خصوصی و حساب ACME در volumeهای `caddy_data` و `caddy_config` نگهداری می‌شوند، نه در Git. **از `docker compose down -v` استفاده نکنید** تا این اطلاعات حذف نشوند. خاموش‌ماندن طولانی سیستم ممکن است گواهی را منقضی کند؛ بعد از روشن‌شدن، باید برای تمدید صبر کنید.

برای IP عمومی متفاوت، در فایل `.env` ریشهٔ پروژه مقدار `ZAR_PUBLIC_IP=YOUR_STATIC_IP` را قرار دهید و کانتینرها را دوباره ایجاد کنید. مقدار پیش‌فرض در Compose برابر `86.104.86.188` است. این مقدار را فقط به IP تحت کنترل خودتان تغییر دهید.

از اینترنت بیرون خانه (مثلاً اینترنت موبایل) آدرس عمومی را بررسی کنید. اگر مودم NAT loopback ندارد، برای بررسی گواهی از خود میزبان بدون دورزدن اعتبارسنجی از دستور زیر استفاده کنید:

```bash
curl --connect-to 86.104.86.188:443:127.0.0.1:443 https://86.104.86.188/ -I
```

سرویس و تایمر قبلی `zar-boot` همچنان همین Compose را اجرا می‌کنند؛ Caddy پس از سالم‌شدن فرانت‌اند شروع می‌شود.

## داده‌ها و اسرار

- پوشهٔ فعلی `backend/pb_data` مستقیم به کانتینر متصل است؛ اطلاعات و فایل‌های فعلی حفظ می‌شوند و داخل ایمیج کپی نمی‌شوند.
- شروع PocketBase ممکن است migrationهای اجرا‌نشدهٔ همین پروژه را اعمال کند؛ برای همین پشتیبان‌گیری قبل از شروع ضروری است.
- پوشهٔ `frontend/app_backups` نیز مستقیم متصل است؛ پشتیبان‌های قبلی باقی می‌مانند.
- فایل `frontend/.env` فقط هنگام اجرا تزریق می‌شود و داخل ایمیج قرار نمی‌گیرد. فایل کامل خروجی `docker compose config` را به اشتراک نگذارید، چون ممکن است اسرار را نمایش دهد.
- سه کانتینر شبکهٔ یکسانی دارند و آدرس داخلی دیتابیس `http://127.0.0.1:8090` است. پورت‌ها در سرویس PocketBase منتشر می‌شوند. پورت داخلی 8090 را بدون اصلاح آدرس داخلی برنامه و Caddy تغییر ندهید.
- قالب raw در env_file از تفسیر علامت دلار در رمزها جلوگیری می‌کند؛ مقادیر این فایل باید بدون کوتیشن اضافی دور مقدار باشند.
- اطلاعات محرمانه را به build argumentها یا متغیرهای `NEXT_PUBLIC_*` ندهید.
- فرانت‌اند با Node.js اجرا می‌شود؛ Bun فقط در مرحلهٔ ساخت استفاده می‌شود.
- فایل اجرایی موجود PocketBase مخصوص Linux amd64 است. در سیستم ARM باید فایل اجرایی مناسب جایگزین و platform سرویس اصلاح شود.

## توقف، به‌روزرسانی و بازگشت به اجرای قبلی

```bash
sudo docker compose down
sudo docker compose up -d --build
```

توقف کانتینرها داده‌های متصل‌شده را حذف نمی‌کند. برای بازگشت به لانچر قبلی، اول `docker compose down` را اجرا کنید و سپس `./start.sh`؛ لانچر تغییر نکرده است.

## بررسی‌ها

**تست‌ها را روی کپی جداگانه و بدون داده‌ها و اسرار واقعی اجرا کنید.** برخی تست‌ها مستقیماً به `backend/pb_data/data.db` می‌نویسند. دستورهای زیر فقط در چنین کپی آزمایشی اجرا شوند:

```bash
cd frontend
bun test tests/
DOCKER_BUILD=1 NEXT_DIST_DIR=.next-docker-check bun run build
```

خروجی standalone تنها با `DOCKER_BUILD=1` فعال می‌شود و اجرای توسعهٔ قبلی را تغییر نمی‌دهد. Docker build فایل‌های محیطی میزبان را نمی‌خواند. بعد از اجرای کانتینرها، ورود به حساب، نمایش تصاویر، چاپ PDF و ساخت پشتیبان را بررسی کنید.
